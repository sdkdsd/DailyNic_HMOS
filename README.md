## 本地使用流程（尚需手机验证）

1. 安装本 fork 的签名测试包后，从“课时与校历设置”填写官方校历的第 1 教学周周一、每节起止时间及核对依据。提供本人上传的教务处本学期校历（2026-08-31开始、20周）及个人截图第1–8节作息草稿，保存前须核对；晚间第9–11节仍待补齐。夏冬季按北京时间5月1日和10月1日自动切换；节假日补课映射仍未实现，不沿用中科大作息。
2. 在课表菜单选择联网获取，在应用内学校网页亲自登录。分别读取全部教学周的学生和班级整张课表，核对首周日期及合并预览后确认。再次读取同学期会更新已有在线学期，离线保留最近结果；也可手动补充课程。单双周用教学周序号，周日属于前一个周一开始的那一周。
3. 考试和待办可手动管理，考试时间按北京时间解析并校验。日历写入由用户主动触发、授权；变化后重新生成并核对。桌面卡片刷新由系统调度，需真机验证。
4. 联网课表使用临时 WebView 会话，退出后可能需要本人重新登录；其他官方入口仍可用系统浏览器。应用不保存密码、不读取 Cookie、不注册凭据桥接，也不自动执行选课、预约、支付等业务。
5. 文件导入为备用方式：单季 `sust-xian-1` 或双季 `sust-xian-2-seasonal` JSON，须匹配当前课时配置，预览确认后整批追加为本地学期。备份不包含完整考试、待办、图片等数据；系统完整备份未实测。电脑可离线转换已支持的可见教务表格；不支持直接 Excel/PDF 导入。

## 验证与构建

主机逻辑测试无需安装依赖，使用现有 Node 24：

```bash
node --test tests/*.test.mjs
bash build.sh --check
```

在已经具备 HarmonyOS 工具链的环境中：

```bash
# 仅在本地配置文件不存在时复制；不要覆盖已有签名配置
cp -n build-profile.json5.bak build-profile.json5
bash build.sh
```

`build.sh` 会使用存在的 `/workspace/.cloud-tools/dailynic/activate.sh`，或 PATH 中的 `hvigorw` / 显式 `HVIGORW`。它不安装软件、不生成密钥、不提高目标 SDK、不停止已有构建守护进程、不安装到手机。依赖缺失时按构建文档先审查安装步骤。

本版本**无需创建 `Encryption.ets` 或生成 RSA 密钥**；上游模板仅留作历史参考，不被应用导入。本地签名文件、证书、密钥、个人课表都不能提交到仓库。
